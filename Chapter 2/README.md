# Chapter 02 – Assignment – Igniting our App

## 1. What is NPM?

NPM (Node Package Manager) is the default package manager for Node.js. It is a repository that contains millions of open-source packages (libraries) that developers can install and use in their projects. It also helps us manage the dependencies of a project.

---

# 2. What is Parcel/Webpack? Why do we need it?

Parcel and Webpack are **module bundlers**. They bundle all the files (JavaScript, CSS, images, fonts, etc.) of our project into optimized files that are ready for production.

We need them because they:

* Bundle multiple files into fewer files.
* Optimize the application.
* Improve performance.
* Provide features like Hot Module Replacement (HMR), Tree Shaking, Minification, Caching, etc.

---

# 3. What is `.parcel-cache`?

`.parcel-cache` is a folder automatically created by Parcel.

It stores the cache of previous builds. When we make changes to our project, Parcel uses this cached data instead of rebuilding everything from scratch. This makes rebuilds much faster and improves development speed.

---

# 4. What is `npx`?

`npx` is a package runner that comes with npm.

It is used to execute npm packages without installing them globally.

Example:

```bash
npx parcel index.html
```

Here, `npx` runs Parcel directly.

---

# 5. What is the difference between `dependencies` and `devDependencies`?

### dependencies

These are the packages required for the application to run in production.

Examples:

* React
* ReactDOM

### devDependencies

These packages are only required during development and build time.

Examples:

* Parcel
* Jest
* ESLint

---

# 6. What is Tree Shaking?

Tree Shaking is an optimization feature provided by modern bundlers like Parcel and Webpack.

It removes unused code (dead code) from the final production bundle, making the application smaller and faster.

For example, if we have 20 functions in a file but use only 5 of them, the remaining unused functions will be removed from the production build.

---

# 7. What is Hot Module Replacement (HMR)?

Hot Module Replacement (HMR) is a feature of Parcel that updates only the modified module without refreshing the entire page.

This makes development much faster because we can instantly see the changes without losing the current application state.

# 9. What is `.gitignore`? What should we add and not add into it?

`.gitignore` is a file that tells Git which files and folders should not be tracked or pushed to the remote repository.

Generally, files that can be regenerated should be added to `.gitignore`.

### Examples:

* `node_modules/`
* `.parcel-cache/`
* `dist/`
* `.env`

We should **not** add source code files like:

* `src/`
* `package.json`
* `package-lock.json`

because they are important for the project.

---

# 10. What is the difference between `package.json` and `package-lock.json`?

## package.json

* Contains project information.
* Lists dependencies and scripts.
* Stores version ranges (approximate versions).

Example:

```json
"react": "^19.0.0"
```

## package-lock.json

* Automatically generated by npm.
* Stores the exact versions of every installed package.
* Ensures everyone installs the exact same dependency versions.

---

# 11. Why should I not modify `package-lock.json`?

`package-lock.json` is automatically generated by npm.

It keeps track of the exact versions of all installed dependencies. Modifying it manually can create dependency conflicts or cause different environments to install different package versions.

It should only change when dependencies are added, removed, or updated using npm commands.

---

# 12. What is `node_modules`? Is it a good idea to push that on Git?

`node_modules` is the folder where npm installs all the project's dependencies.

It contains all the packages required by the application.

It is **not** a good idea to push it to Git because:

* It is very large.
* It can always be regenerated using:

```bash
npm install
```

Therefore, it should be added to `.gitignore`.

---

# 13. What is the `dist` folder?

The `dist` folder is automatically generated when we create a production build using Parcel.

It contains the optimized production-ready files such as:

* Bundled JavaScript
* Optimized CSS
* Images
* HTML

These files are deployed to the server.

---

# 14. What is `browserslist`?

`browserslist` is a configuration used by tools like Parcel, Babel, and Autoprefixer.

It tells these tools which browsers our application should support.

Based on this configuration, Parcel generates code that is compatible with those browsers.

Example:

```json
"browserslist": [
  "last 2 Chrome versions",
  "last 2 Firefox versions"
]
```

# 16. Read about `^` (Caret) and `~` (Tilde)

## Caret (`^`)

Allows updates to **minor** and **patch** versions while keeping the same **major** version.

Example:

```json
"react": "^19.0.0"
```

Can install:

* 19.0.1 ✅
* 19.1.0 ✅
* 19.5.2 ✅
* 20.0.0 ❌

---

## Tilde (`~`)

Allows updates only to the **patch** version.

Example:

```json
"react": "~19.0.0"
```

Can install:

* 19.0.1 ✅
* 19.0.5 ✅
* 19.1.0 ❌

---

# 17. Script types in HTML

There are three commonly used script loading methods.

## Normal Script

```html
<script src="app.js"></script>
```

The browser downloads and executes the script immediately, blocking HTML parsing.

---

## Async

```html
<script async src="app.js"></script>
```

The script downloads in parallel and executes as soon as it finishes downloading. Execution order is **not guaranteed**.

---

## Defer

```html
<script defer src="app.js"></script>
```

The script downloads in parallel but executes only after the HTML document has been completely parsed.

`defer` is generally preferred for most applications because it doesn't block HTML parsing and preserves the execution order of scripts.
